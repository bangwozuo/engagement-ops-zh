# 回复话术建议流程（reply-script-advice-flow）

> 触发：人工 / 事件（每日评论聚合流程产出处理队列后）
> 产出：回复工单（Excel，逐条对齐评论 ↔ 草稿 ↔ 一致性检查）
> 价值：把「想一句回一句」的随意回复变成「草稿 → 质检 → 人工确认」的可控流水线，
> 人设一致性可量化（≥80 分）

# 流程目标

给高优先级评论（黑粉/吐槽/提问）配齐**过人设一致性检查的回复草稿**，以工单形式
交人工确认发布。核心纪律：**发布率 0%**——脚本与模型都不执行发布，工单是终点，
发布动作永远由人执行。

# 步骤明细（每步含输入/处理/输出/失败处理）

## 步骤 1：评论优先级过滤

| 项 | 内容 |
|---|---|
| 技能 | `comment-sentiment-analyze`（scripts/sentiment_scan.py） |
| 输入 | 当日评论流（同 daily-comment-aggregate-flow 的输入） |
| 处理 | 四分类 + SLA 排序 → 取高优队列（黑粉 30 分钟 / 吐槽 2 小时 / 提问 4 小时）；赞美与闲聊不进本流程 |
| 输出 | out/sentiment.json（高优子集用于步骤 3 对齐） |
| 失败处理 | 退出码 ≠0 → 中止打印 stderr；全部评论为赞美/闲聊 → 正常退出，工单标「本期无高优评论」；评论为空 → 占位工单退出 |

## 步骤 2：草稿一致性检查

| 项 | 内容 |
|---|---|
| 技能 | `persona-voice-library`（scripts/voice_check.py） |
| 输入 | 语气库档案（voice）+ 针对高优评论的回复草稿（drafts） |
| 处理 | 逐条打分：称呼 40 + 口头禅 20 + 句长 20 + 零违禁 20，≥80 达标；效果承诺/绝对化/站外导流任一命中 → 合规否决 |
| 输出 | out/voice_check.json（逐条得分与判定） |
| 失败处理 | 退出码 ≠0 → 中止；语气库字段缺失（无称呼词表）→ 中止并列缺失清单，不用默认词表硬检；草稿引用不存在的评论 ID → 保留在工单标「评论不存在」 |

## 步骤 3：工单对齐（内置汇合）

| 项 | 内容 |
|---|---|
| 输入 | 步骤 1 的高优评论 + 步骤 2 的检查结果 |
| 处理 | 按 comment_id 对齐，生成工单状态机：<br>• 有草稿且达标 → **待人工确认**（确认后人工发布）<br>• 有草稿但不达标 → **需改写**（缺哪项补哪项后重检）<br>• 合规否决 → **禁止发布**（附违禁明细，不给变通写法）<br>• 高优评论无草稿 → **待生成**（交模型按 reply-script-generate 生成，再回步骤 2 重检） |
| 输出 | out/回复工单.xlsx（禁止发布行标红）+ out/advice_flow_result.json |
| 失败处理 | 任一上游产物缺失 → 中止；草稿覆盖率 < 80% → 工单汇总标注「备稿不足」，建议扩大草稿覆盖后再处理队列 |

# 量化规则（判定不看感觉）

- 一致性达标线 80 分；分项权重 40/20/20/20（与 persona-voice-library 完全对齐）
- 高优评论草稿覆盖率 = 有草稿的高优评论 ÷ 高优评论总数，**< 80% 标备稿不足**
- 工单 SLA：黑粉 30 分钟内确认、吐槽 2 小时内、提问 4 小时内（继承上游分类）
- 批次统计：待人工确认 / 需改写 / 禁止发布 / 待生成 四态计数；**发布率恒为 0%
  （发布由人工执行），连续出现「禁止发布」> 30% 说明上游生成环节失控需回炉**

# 失败模式（编排层特有）

- **草稿与评论错配**：comment_id 写错会让一条黑粉评论配上赞美回复——工单逐条显示
  对应评论摘要，人工确认时必须读一眼再放行
- **口头禅堆砌过关**：为刷分每条塞 2-3 个口头禅，命中率上去了机器人感也上去了——
  模型复核允许每条 ≤1 个，超出判「需改写」而非达标
- **确认环节形同虚设**：工单攒 3 天一起点确认 = 无人复核；SLA 时限就是给确认环节
  定的，超时进复盘
- **禁用词表与平台规则不同步**：平台新增敏感词后语气库未更新会出现「检查全过但
  平台违规」——语气库每月随平台规则校对一次

# 输出格式（回复工单）

```markdown
## 回复工单
| 评论ID | 用户 | 类别 | SLA | 评论摘要 | 草稿ID | 一致性得分 | 工单状态 | 下一步 |
|---|---|---|---|---|---|---|---|---|

## 汇总
| 项 | 内容 |
|---|---|
| 高优评论数 / 已备草稿 | n / n |
| 待人工确认 / 需改写 / 禁止发布 / 待生成 | n / n / n / n |
| 发布率红线 | 0% —— 所有回复经人工确认后才对外 |
```

# 编排规则

- DAG 节点 = 本仓真实技能 slug：`comment-sentiment-analyze`、`persona-voice-library`、
  `reply-script-generate`（草稿生成环节）
- 步骤间经 JSON 文件衔接；模型只介入草稿生成与语气自然度复核
- 四态状态机是本流程的核心交付：每条高优评论在任何时刻都有明确去向

# 合规

- 工单标注「AI 生成内容」；**发布率红线 0%**，所有回复经人工确认后由人工发布
- 合规否决（效果承诺/绝对化/站外导流）不给任何变通写法
- 工单含用户评论内容，仅限本账号运营使用，不外发
