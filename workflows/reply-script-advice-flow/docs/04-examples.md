# 使用示例

以下示例均来自 `examples/input.json` 的 `run_flow.py` 实跑结果（退出码 0）。

## 示例 1：标准输入 —— 6 条高优评论的四态工单

**输入**（节选）：

```json
{
  "comments": [{"id": "C003", "user": "黑粉本粉", "text": "就是骗子！收钱恰烂饭，大家都别买，我去举报了😡", "likes": 1}],
  "voice": {"称呼": ["宝子", "姐妹"], "口头禅": ["亲测"], "句长上限": 20, "禁用词": ["亲～"]},
  "drafts": [{"id": "D3", "comment_id": "C003", "text": "亲～本产品 100% 正品保证，加微信还有专属优惠哦！"}]
}
```

**输出**：`out/回复工单.xlsx`——待人工确认 3 / 需改写 1 / 禁止发布 1 / 待生成 1，
草稿覆盖率 83%。详见 examples/output.md。

## 示例 2：整改前后对照 —— 从"随手回"到"工单流水线"

**场景**：同一天 6 条高优评论。

| 阶段 | 做法 | 风险 |
|---|---|---|
| 改造前 | 想一句回一句；外包代写的一条带「加微信」的回复直接发出 | 导流违规扣分；语气与人设不符 |
| 改造后 | 草稿全部过一致性检查：D3 被合规否决拦下（禁止发布），D4 需改写，达标 3 条人工确认后发布 | 违规回复在流程内被拦截 |

**关键差异**：D3 那条回复如果没有质检环节就发出，后果是平台导流处罚 + 品牌方
看到"亲～"客服腔质疑人设——一条回复的翻车成本远高于一次质检。

## 示例 3：待生成的正确处理

**场景**：C011「油皮用了会闷痘吗？」无对应草稿。

**输出**：工单标「待生成」，下一步指明路径：交模型按 reply-script-generate 生成
（引用 FAQ「油皮能用吗」簇答案要点：肤质口径 + 个体差异 + 建议就医）→ 回步骤 2
重检 → 达标后转「待人工确认」。**流程不中断、不降质**——缺稿不等于可以乱回。

## 示例 4：草稿覆盖率不足的预警

**输入**：8 条高优评论只有 4 条有草稿（覆盖率 50% < 80%）。

**输出**：工单正常产出 4 条，但汇总标红「备稿不足：草稿覆盖率 50%（下限 80%），
建议先补齐剩余 4 条草稿再进入确认环节」。避免"确认了 4 条、漏了 4 条"的
半吊子处理——高优评论的 SLA 不会因为备稿不足而暂停。

## 示例 5：禁用词表过期被模型拦截

**输入**：平台本周新增敏感词「XX 咖」；语气库未更新，草稿 D7 含该词。

**输出**：脚本词表未命中（全过），但模型按 prompt 的月度校对要求复核发现 →
工单备注「词表外平台新敏感词，建议人工确认前核对平台最新规范」→ 人工拦下。
**机器词表 + 模型复核双层防线**是本流程的设计前提。
