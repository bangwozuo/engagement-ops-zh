# 使用示例

以下示例均来自 `examples/input.json` 的 `run_flow.py` 实跑结果（退出码 0）。

## 示例 1：标准输入 —— 2 周互动数据的周更名单

**输入**（节选）：

```json
{
  "account": "@小鹿的好物日记",
  "weeks": 2,
  "interactions": [
    {"user": "奶盖不加糖", "type": "comment", "sentiment": "pos"},
    {"user": "奶盖不加糖", "type": "dm", "sentiment": "neutral"},
    {"user": "打工人小王", "type": "comment", "sentiment": "neg"}
  ]
}
```

**输出**：`out/铁粉维护名单.xlsx`——铁粉候选 2 / 需安抚 1 / 黑粉观察 1，
含私域移交确认清单。奶盖不加糖 75.7 分（≥70）可邀共创。详见 examples/output.md。

## 示例 2：整改前后对照 —— 粉丝维护从「凭感觉」到「凭名单」

**场景**：创作者每周随机回复几条老粉评论，从没给粉丝群发过专属福利。

| 阶段 | 做法 |
|---|---|
| 改造前 | 贡献 90% 互动的核心粉与普通路人获得同样（少得可怜的）关注；核心粉流失无感知 |
| 改造后 | 周一名单：2 位铁粉候选 → 感谢 + 福利 + 进群邀请（人工确认后执行）；评分 75.7 的奶盖不加糖受邀参与下期选题投票 |
| 结果 | 维护精力投向贡献大头；铁粉的「被看见感」是私域转化前最重要的信任积累 |

## 示例 3：零候选的正确行为

**输入**：某新号 2 周内无一人达到「≥5 次/周 且 正情感率 ≥60%」。

**输出**：名单显示「（本周无铁粉候选）」，并附提示：
「检查阈值（≥5 次/周 且 正情感率 ≥60%）或延长统计周期」——
**不降低标准凑名单**：新号该做的是互动钩子（结尾提问、评论区梗），
不是把路人包装成铁粉。

## 示例 4：疑似刷量号拦截

**输入**：用户「互赞小分队-03」2 周 14 次互动、全部 like、无文本。

**输出**：机器统计落「高潜互动」，但名单备注「疑似互赞群（批量命名特征/无文本互动），
待模型复核，暂不进名单」——若混进名单发了福利，预算烧在假粉上等于浪费。

## 示例 5：sentiment 覆盖率不足的标红

**输入**：50 条互动记录中 45 条无 sentiment 字段（上游情感分类未跑）。

**输出**：流程正常跑完但汇总标红：「sentiment 覆盖率 10%（<50%），分层可信度低，
建议先补跑 daily-comment-aggregate-flow 的情感分类」。**宁可标红也不输出
看似完整的错误名单**——情感档错误会让需安抚用户被当路人忽略。
