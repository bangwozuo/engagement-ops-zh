# 每日评论聚合分类流程（daily-comment-aggregate-flow）

> 触发：定时，每日 21:00（发布高峰后 1-2 小时，评论量最全的时点）
> 产出：每日评论处理日报（Excel）· 耗时目标：人工介入前 ≤ 5 分钟
> 价值：评论处理 1-2 小时 → 约 20 分钟，月省约 30 小时

# 流程目标

把当天全部评论压成一张**按 SLA 排好序的处理队列**：运营者打开日报就知道
「先回哪条、每类花几分钟」，而不是从上往下漫无目的地刷评论。

# 步骤明细（每步含输入/处理/输出/失败处理）

## 步骤 1：评论四分类 + 强度打分

| 项 | 内容 |
|---|---|
| 技能 | `comment-sentiment-analyze`（scripts/sentiment_scan.py） |
| 输入 | 当日评论流（id/user/text/likes；从平台后台导出或人工粘贴） |
| 处理 | 词表+表情权重四分类（提问/赞美/吐槽/黑粉/闲聊兜底）+ 强度 1-5 打分 |
| 输出 | out/sentiment.json（逐条分类结果）+ out/评论分类处理清单.xlsx |
| 失败处理 | 脚本退出码 ≠0 → 流程中止并打印 stderr（不静默失败）；评论内容为空 → 进存疑项清单，不猜分类；上游依赖缺失 → 按脚本提示安装后重跑 |

## 步骤 2：SLA 队列拆分（内置规则，无需模型）

| 项 | 内容 |
|---|---|
| 输入 | 步骤 1 的 sentiment.json |
| 处理 | 按「黑粉 30 分钟内 > 吐槽 2 小时 > 提问 4 小时 > 赞美点赞 > 闲聊可不回」拆成 5 个队列；同级内部按强度降序、点赞降序 |
| 输出 | 每日评论处理日报.xlsx 的「SLA队列总览」sheet |
| 失败处理 | sentiment.json 缺失/损坏 → 中止并提示重跑步骤 1；评论数为 0 → 输出「今日无评论」占位日报并正常退出（不算失败） |

## 步骤 3：人工执行队列（流程终点，AI 不越界）

| 项 | 内容 |
|---|---|
| 输入 | 日报中的处理队列 |
| 处理 | 运营者按队列顺序处理：黑粉回复走 reply-script-advice-flow 生成草稿；提问类次日进 faq-to-topic-flow 聚类 |
| 输出 | 处理完成标记（人工维护） |
| 失败处理 | 高优评论草稿缺失 → 工单标「待生成」交模型补；黑粉二次攻击 → 人工执行隐藏/举报，流程不自动执行任何平台操作 |

# 量化规则（判定不看感觉）

- 分类四分法与强度 1-5：见 comment-sentiment-analyze（词表+表情权重，封顶 5）
- SLA 时限：黑粉 30 分钟 / 吐槽 2 小时 / 提问 4 小时 / 赞美点赞即可
- **负类合计占比 > 50%**：当天属「舆情异常日」，先排查是否有爆款负面外因
  （被大 V 转发、差评扩散），再做日常队列
- **提问占比 > 40%**：内容信息密度不足（说明评论区在替内容补信息），
  次日选题参考 faq-to-topic-flow 结果

# 失败模式（编排层特有）

- **评论导出截断**：平台后台一次最多导 N 条，爆款日会漏——日报必须记录「输入条数」，
  运营者对照平台显示的评论总数核对，缺了就分批导
- **时区/日期切分**：21:00 跑的是「今天 00:00-21:00」，21:00 后的评论进明天的日报，
  别把两天混在一个文件里
- **重复导入**：同一天跑两次流程，评论会重复计数——导入前按评论 ID 去重
- **上游分类误判传导**：词表脚本把老粉玩笑判成黑粉会让 30 分钟队列失真，
  执行前扫一眼存疑项清单（反讽/玩笑由模型复核）

# 输出格式（每日评论处理日报）

```markdown
## SLA 队列总览
| 队列 | 条数 | 说明 |
|---|---|---|
| 🔴 30 分钟内 | n | 黑粉：澄清+隐藏/举报，禁止对线 |
| 🟠 2 小时内 | n | 吐槽：致歉+改进点 |
| 🟡 4 小时内 | n | 提问：答案或站内指引 |
| 🟢 点赞即可 | n | 赞美：点赞+高赞置顶 |
| ⚪ 可不回 | n | 闲聊：每 2 小时集中扫 |

## 处理队列（逐条）
| 评论ID | 用户 | 类别 | 强度 | 处理时限 | 建议动作 | 命中依据 |
|---|---|---|---|---|---|---|

## 异常信号
1. 负类合计占比：x%（>50% 舆情异常日）
2. 输入条数核对：导出 n 条 / 平台显示 m 条
```

# 编排规则

- 每步的技能资产必须真实存在（skills/comment-sentiment-analyze/）
- 步骤间通过 JSON 文件衔接（out/sentiment.json），禁止在提示词里传递大段原文
- 全流程无模型调用依赖；模型只在两处介入：分类复核（存疑项）与回复草稿生成
- 所有对外动作（回复/隐藏/举报）人工执行，流程产出只是队列与建议

# 合规

- 日报标注「AI 生成内容」，仅内部使用
- 用户昵称与评论内容不出本账号运营范围；日报文件不外发
- 隐藏/举报/回复全部人工执行；流程不持有任何平台写权限
