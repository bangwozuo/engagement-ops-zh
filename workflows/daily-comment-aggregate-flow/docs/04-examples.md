# 使用示例

以下示例均来自 `examples/input.json` 的 `run_flow.py` 实跑结果（退出码 0）。

## 示例 1：标准输入 —— 12 条评论的每日日报

**输入**（节选）：

```json
{
  "account": "@小鹿的好物日记",
  "platform": "抖音",
  "date": "2026-09-29",
  "comments": [
    {"id": "C001", "user": "奶盖不加糖", "text": "姐这个粉底液色号是多少呀？黄二白能用吗", "likes": 12},
    {"id": "C003", "user": "黑粉本粉", "text": "就是骗子！收钱恰烂饭，大家都别买，我去举报了😡", "likes": 1}
  ]
}
```

**输出**：`out/每日评论处理日报.xlsx`——SLA 队列总览 + 逐条处理队列（黑粉标红）。
12 条评论：黑粉 2 / 吐槽 3 / 提问 3 / 赞美 3 / 闲聊 1，需 2 小时内处理 5 条。

## 示例 2：整改前后对照 —— 从"刷评论"到"按队列处理"

**场景**：同一天 12 条评论。

| 阶段 | 做法 | 耗时 |
|---|---|---|
| 改造前 | 从上往下刷评论，先回了 3 条赞美（轻松），2 条黑粉在评论区挂了 4 小时被顶上热评 | 1-2 小时，重点失焦 |
| 改造后 | 打开日报 → 🔴 队列 2 条黑粉 30 分钟内澄清 → 🟠 3 条吐槽给改进点 → 🟡 3 条提问 → 赞美批量点赞+置顶 C004 | 约 20 分钟 |

**关键差异**：黑粉评论被顶上热评的二次传播损失远大于回复成本，SLA 队列的本质是
把「先救火」制度化。

## 示例 3：舆情异常日触发

**输入**：某日 40 条评论中黑粉 9、吐槽 14（负类合计 57.5%）。

**输出**：日报异常信号标注「负类合计占比 57.5%（>50%）→ 舆情异常日」。
处置顺序变化：先查外因（昨日视频是否被大 V 差评转发/买了推广被竞品盯上），
确认外因后统一口径回复，而不是逐条按日常队列消耗——异常日套日常流程会越回越乱。

## 示例 4：导出截断的核对拦截

**输入**：爆款日评论实际 320 条，平台后台单次只导出 100 条。

**输出**：日报汇总记录「输入条数 100」，运营者对照平台显示的 320 条发现截断 →
分 4 批导出合并（按评论 ID 去重）后重跑。**若不核对，日报会以 1/3 样本得出
错误结论**（可能恰好漏掉负面集中区）。

## 示例 5：空评论日的正常退出

**输入**：`comments: []`（停更日）。

**输出**：「今日无评论」占位日报，退出码 0——不算失败，明天见。
不报错、不编数据，保持流程日志连续。
