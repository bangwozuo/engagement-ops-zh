# 使用示例

以下示例均来自 `examples/input.json` 的脚本实跑结果（退出码 0）。

## 示例 1：标准输入 —— 12 条混合评论的每日分拣

**输入**（节选）：

```json
{
  "account": "@小鹿的好物日记",
  "platform": "抖音",
  "date": "2026-09-29",
  "comments": [
    {"id": "C001", "user": "奶盖不加糖", "text": "姐这个粉底液色号是多少呀？黄二白能用吗", "likes": 12},
    {"id": "C003", "user": "黑粉本粉", "text": "就是骗子！收钱恰烂饭，大家都别买，我去举报了😡", "likes": 1},
    {"id": "C004", "user": "cccccc", "text": "绝了绝了这个色号也太好看了吧！！爱了❤️", "likes": 45}
  ]
}
```

**输出**（脚本实跑）：黑粉 2 / 吐槽 3 / 提问 3 / 赞美 3 / 闲聊 1；负类合计占比 41.7%，
需 2 小时内处理 5 条。C003 命中「骗子/恰烂饭/都别买 + 😡」判黑粉（强度 5，30 分钟内）；
C004 含弱信息寻求词「色号」但有「绝了 + ❤️」正情绪佐证，判赞美而非提问（误判拦截）。

## 示例 2：整改前后对照 —— 黑粉评论的处理路径

**场景**：C003「就是骗子！收钱恰烂饭，大家都别买，我去举报了😡」

| 阶段 | 内容 |
|---|---|
| 分类前 | 运营者刷到后情绪上头，想直接回怼「你才骗子」 |
| 分类后 | 黑粉（强度 5），SLA 30 分钟内，动作 = 澄清一次 + 视情节隐藏/举报 |
| 正确动作草稿 | 「订单与检测报告都在置顶视频 1 分 20 秒处，如认为售后有问题请私信订单号，会核实处理。」（人工确认后发布，禁止二次对线） |
| 错误动作（禁止） | 回怼 / 删评 / 公开点名 / 拉黑后闲聊区嘲讽 |

## 示例 3：边界案例 —— 提问与赞美的混淆纠正

**场景**：C004「绝了绝了这个色号也太好看了吧！！爱了❤️」

- 若只看「色号」这个信息寻求词，会误判为提问（4 小时 SLA）
- 脚本规则：弱线索（色号/链接/价格等）必须无赞美词、无正表情佐证才判提问
- 实跑判定：赞美（强度 4）——只需点赞 + 置顶，不占用 4 小时回答队列

**反例**：C001「姐这个粉底液色号是多少呀？黄二白能用吗」有强疑问句式（？/吗），
即使语气友好也判提问——两类评论的用户诉求完全不同。

## 示例 4：数据缺失的正确行为

**输入**：`{"id": "C013", "user": "神秘用户", "text": "", "likes": 0}`

**输出**：不计入分类，进入「存疑项」清单：

```markdown
## 存疑项
1. C013（神秘用户）：评论内容为空，无法分类。请补全文本后重跑。
```

不猜内容、不填默认分类——空评论可能是加载失败或被平台折叠，猜了会污染统计。
