# 使用示例

以下示例均来自 `examples/input.json` 的脚本实跑结果（退出码 0）。

## 示例 1：标准输入 —— 一批草稿的人设一致性质检

**输入**（节选）：

```json
{
  "voice": {
    "称呼": ["宝子", "姐妹", "家人们"],
    "口头禅": ["码住", "冲鸭", "亲测", "说真的"],
    "句长上限": 20,
    "禁用词": ["绝绝子", "yyds", "亲～"]
  },
  "drafts": [
    {"id": "D1", "comment_id": "C001", "text": "宝子，黄二白建议选 12 号，亲测不假白，色号对比在置顶视频码住～"}
  ]
}
```

**输出**（脚本实跑）：6 条草稿达标 4（67%），合规否决 1。D1 得 100 分
（称呼 + 双口头禅 + 句长 7.8 字 + 零违禁），可直接进入人工确认队列。

## 示例 2：整改前后对照 —— 一条翻车回复的修正

**场景**：D4「亲～本产品 100% 正品保证，绝绝子好用，加微信还有专属优惠哦！」

| 阶段 | 内容 |
|---|---|
| 检查前 | 草稿由外包运营代写，语气与人设完全不符且带导流 |
| 检查后 | 得 20 分，三重合规否决（100% 承诺 / 禁用词 ×2 / 加微信导流）→ **禁止发布** |
| 改写（人工确认后） | 「宝子，正品渠道和检测报告都放在置顶视频了，小黄车直接下单哦～」——复检得 80 分 |

**禁止**：不提供「＋薇」「加v信」式变通——那是规避审核，属违规协助。

## 示例 3：一致性过头的机器人感

**场景**：连续 10 条草稿每条都以「宝子～」开头且都含「码住」。

- 机器检查：命中率 100%，全部达标
- 模型复核：判「机器人感」——口头禅一条回复 1 个足矣，称呼允许 20% 自然变体
  （老粉直接喊昵称）。建议：D3 这类短回复（80 分，缺口头禅）**不用强行补**，
  保住自然度比刷分重要

## 示例 4：B 端账号的禁用词表差异

**场景**：同一位创作者的官方合作号，语气库换为：

```json
{"称呼": ["您好"], "口头禅": [], "禁用词": ["绝绝子", "yyds", "家人们", "宝子", "冲鸭"]}
```

**输出**：同样的草稿 D1（含"宝子"）在该档案下判不达标——称呼不在词表。
**多账号必须各用各的档案**，A 号口头禅出现在 B 号 = 穿帮。

## 示例 5：档案字段缺失的正确行为

**输入**：`voice` 缺 `称呼` 字段。

**输出**：不执行检查，返回清单：
「语气库缺少『称呼』字段——请先访谈创作者补齐（建议 2-4 个，按亲密度排序），
档案基于历史回复抽样整理，不是问出来的理想语气」。
