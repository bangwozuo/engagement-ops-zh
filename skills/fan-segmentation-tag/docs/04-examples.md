# 使用示例

以下示例均来自 `examples/input.json` 的脚本实跑结果（退出码 0）。

## 示例 1：标准输入 —— 2 周互动记录的九宫格分层

**输入**（节选）：

```json
{
  "account": "@小鹿的好物日记",
  "weeks": 2,
  "interactions": [
    {"user": "奶盖不加糖", "type": "comment", "sentiment": "pos"},
    {"user": "奶盖不加糖", "type": "dm", "sentiment": "neutral"},
    {"user": "打工人小王", "type": "comment", "sentiment": "neg"}
  ]
}
```

**输出**（脚本实跑，52 条互动 / 10 名粉丝）：铁粉候选 3 / 需安抚 1 / 黑粉观察 1。
奶盖不加糖 10 次互动（周均 5.0）、8 正 0 负、1 次私信 → 铁粉评分 75.7，居榜首。

## 示例 2：整改前后对照 —— 「高频互动 = 铁粉」的错误认知

**场景**：打工人小王 2 周 10 次互动，运营者最初把他当"铁粉"发福利。

| 阶段 | 判定 |
|---|---|
| 只看频次 | 10 次/2 周 = 高频 → 误判铁粉 |
| 加入情感维度 | 正情感率 0%（6 条负面：广告太多、划水…）→ **需安抚** |
| 正确动作 | 2 小时内回复致歉 + 给出剪辑改进点；先查负面是否指向同一问题 |
| 错误动作（禁止） | 给高频负面用户发粉丝福利，等于奖励差评行为 |

## 示例 3：集中度对照 —— 发现「泛流量空转」

**输入**：某周 400 名粉丝、900 次互动，TOP 10% 粉丝（40 人）仅贡献 25% 互动。

**判定**：25% < 30% → 没有核心粉丝群，内容在泛流量里空转。此时不该急着做分层维护，
而是先加互动钩子（结尾提问、评论区固定梗、置顶讨论），把 TOP 10% 占比拉到 60%
以上再跑铁粉流程，否则名单里全是弱互动用户。

## 示例 4：疑似刷量号的复核剔除

**输入**：用户「互赞小分队-03」2 周 14 次互动、全部为 like、无评论内容。

**输出**：机器统计落「高频+中性 = 高潜互动」，但模型按 prompt.txt 复核：
互动全是点赞、无文本、昵称呈批量命名特征 → 判疑似互赞群，
**剔除出任何候选名单**并在名单备注「疑似互赞群，已剔除」——不静默删除。

## 示例 5：数据不足的正确行为

**输入**：`weeks: 1` 且某用户仅 2 次互动。

**输出**：正常分层（低频），但汇总里输出警告：
「统计周期 < 2 周，高频判定噪音大，建议积累 ≥2 周数据后重跑」。
不编造数据、不用单次爆款互动推断粉丝忠诚度。
